Add rate limiting to the public API

Prevent abuse of public API endpoints by capping requests at 100 per minute per IP.

Context

Support flagged repeated scraping — a small set of IPs hitting /api/products every few milliseconds. No rate limiting exists today; the middleware layer is the natural place to add it.

Steps

  1. Add a rateLimit middleware using a sliding-window counter backed by an in-memory LRU cache.
  2. Apply the middleware to every route under /api/* in middleware.ts.
  3. Return 429 Too Many Requests with a Retry-After header once the limit is exceeded.
  4. Add an X-RateLimit-Remaining header to all API responses.
  5. Write a test that bursts 101 requests and asserts the 101st is rejected.

Acceptance criteria

  • >100 requests/min from one IP to any /api/* route returns 429 after the 100th.
  • Traffic under the limit is unaffected — no added latency over 5ms.
  • New test suite passes.

Out of scope

  • No per-user (authenticated) rate limits — IP-based only this pass.
  • No new infra dependency — do not introduce Redis.
